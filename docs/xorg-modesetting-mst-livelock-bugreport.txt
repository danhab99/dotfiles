Why this is an upstream bug
---------------------------
xorg-server 21.1.23 hw/xfree86/drivers/modesetting/vblank.c ms_queue_vblank():

  for (;;) {
      ret = drmCrtcQueueSequence(...) / drmWaitVBlank(...);
      if (ret == 0) return TRUE;
      if (errno != EBUSY) { abort; return FALSE; }
      ms_flush_drm_events(screen);   /* poll(timeout=0); if nothing, returns 0 */
  }

When i915 stops delivering vblank IRQs, ioctl keeps returning EBUSY and flush
returns 0. The loop never sleeps. Xorg pegs one core, i3 IPC dies, input lags.
Killing compositors does not recover. Soft recovery (reattach inputs, skip
RandR) does not recover. Only a new X server recovers.

Present/DRI2 (Electron/Slack, Firefox, Cursor) call this path with no picom.

A related 2015 change switched "abort if flush returns <= 0" to "abort only if
flush < 0" so EINTR/EBUSY could retry. That made flush==0 (empty queue) an
infinite spin.

Proposed upstream patch (already in this NixOS repo)
----------------------------------------------------
subflakes/xorg/patches/ms-queue-vblank-ebusy-no-spin.patch
  If EBUSY and ms_flush_drm_events() <= 0, abort the queue request.
  Logs: "ms_queue_vblank: abort EBUSY spin (flush=%d)"

subflakes/xorg/patches/drmmode-uevent-debounce.patch
  Ignore non-card DRM udev nodes; debounce RRGetInfo/drmModeGetConnector
  to 2s (KVM EDID flaps otherwise force-probe MST AUX on every uevent).

Also local: drop DisplayLink/evdi on this host (TB3 MST, not EVDI). Extra
drm_minor uevents made X reprobe all i915 connectors.

How to reproduce
----------------
1. Intel i915 laptop, 3x DP-MST through a KVM that rewrites EDIDs.
2. Xorg modesetting 21.1.23, i3, GL clients (Slack/Firefox), no compositor.
3. Leave docked overnight or switch KVM away/back.
4. Observe X at ~100% of one core, i915 IRQ rate near 0-2/s (healthy ~100-200/s
   for 3x60Hz), xrandr may still answer, i3-msg hangs.

Expected
--------
USB/KVM blip may drop input briefly. X stays schedulable. Present may miss
frames. Session remains usable.

Actual
------
X livelocks in ms_queue_vblank until the X server is replaced.
